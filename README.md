# 시간 맞춰 가장 저렴하게

목적지와 도착 제한 시각을 입력하면, 그 안에 도착할 것으로 예상되는 대중교통 경로를 비용순으로 비교하고 출발 시각을 알려주는 해커톤 프로젝트입니다.

현재 화면·경로 계산·자동 알림 코드의 첫 버전이 `feature/mvp-core` 브랜치에 있습니다. 실제 카카오 응답과 텔레그램 발송은 키가 없어 아직 확인하지 못했습니다.

## 역할과 목표

| 담당 | 목표 | 완료 기준 |
| --- | --- | --- |
| 저장소 소유자 `Chinakimchi` | 네이버 지도 화면 흐름 분석, 입력·결과 화면 설계, 통합과 발표 | `plan.md` 원본 해부 기록, 화면에서 목적지·제한 시각과 경로 결과 시연 |
| 공동 작업자 `cloniante-prog` | 공식 공개 경로 API 검증, 비용·시간 비교 규칙, 자동 알림 | 실제 API 응답의 시간·요금·단계 확인, 자동 실행과 중복 없는 텔레그램 알림 시연 |
| Codex | 공통 설계와 구현, 테스트, 두 작업의 통합 지원 | 데이터 형식 합의, 코드 검증, 남은 준비 사항 안내 |

두 사람이 함께 결정할 사항은 입력 범위, 경로 후보의 범위, 도착 여유시간, 알림 조건입니다. 결론을 `plan.md`에 남깁니다.

## 개발 순서

1. 네이버 지도 사용 흐름을 읽기 전용으로 분석하고 `plan.md`의 원본 해부를 채웁니다.
2. 공개 API의 실제 응답에서 경로별 소요시간·요금·이동 단계를 확인합니다.
3. 목적지·도착 제한 시각을 입력하는 화면을 만듭니다. (코드 작성 완료, 실데이터 검증 전)
4. 남은 시간 내 도착 가능한 경로를 골라 예상 비용순으로 정렬합니다. (단위 테스트 완료)
5. GitHub Actions와 텔레그램 알림을 연결하고 중복 발송을 검사합니다. (코드 작성 완료, 실제 발송 검증 전)
6. 배포, 출처·키 노출 검사, 시연 자료를 마무리합니다.

초기 MVP는 대중교통 경로와 그 안의 도보·버스·지하철 구간을 대상으로 합니다. 예상 시간과 요금은 실제 도착·지출을 보장하지 않으며, 데이터 제공 범위는 API 실응답 확인 후 확정합니다.

## 협업 방법

- 각자 작업용 브랜치를 만들고, 변경 사항은 Pull Request로 합칩니다.
- 비밀 키와 토큰은 저장소 파일에 적지 않고 GitHub Actions Secrets나 로컬 환경변수에 둡니다.
- 원본 서비스의 앱 파일 또는 비공개 API를 사용하지 않습니다.
- 분석 캡처와 참고 자료를 올리기 전 개인정보나 키가 없는지 확인합니다.

## 준비가 필요한 계정

- 카카오디벨로퍼스 앱과 REST API 키: 공식 대중교통 경로 조회용
- 텔레그램 봇 토큰과 알림받을 채팅 ID: 출발 알림용

키가 준비되면 값은 채팅으로 보내지 말고 저장소의 Secrets에 직접 등록합니다.

## 로컬 실행

Node.js 22 이상이 필요합니다. 이 저장소에서 `node --test`로 계산·중복 방지 테스트를 실행하고, `node server.js`로 화면을 엽니다. 기본 주소는 `http://localhost:3000`입니다.

PowerShell에서는 카카오 REST API 키를 현재 터미널 세션에만 설정한 뒤 서버를 실행할 수 있습니다.

```powershell
$env:KAKAO_REST_API_KEY = '본인 키'
node server.js
```

장소 검색 결과에서 출발지와 목적지를 선택하고 도착 시각을 넣으면 공식 API 응답에서 시간 안에 도착 가능한 경로를 요금순으로 보여줍니다. 키가 없으면 서버 상태 화면은 뜨지만 장소·경로 조회는 사용할 수 없습니다.

## 출발 알림 등록

경로 결과에서 **출발 알림 설정 파일 받기**를 누르면 알림 한 건의 JSON 파일을 받습니다. 그 내용을 `config/monitors.json` 배열에 항목으로 추가해 Pull Request로 합칩니다. 예시 구조는 다음과 같습니다.

```json
[
  {
    "id": "trip-unique-1",
    "origin": { "name": "출발지", "x": 127.0, "y": 37.5 },
    "destination": { "name": "목적지", "x": 127.1, "y": 37.6 },
    "deadline": "2026-10-28T09:00:00.000Z",
    "bufferMinutes": 5
  }
]
```

실제 저장할 때는 화면에서 받은 좌표와 미래 시각을 사용합니다. 최대 5개를 등록할 수 있습니다. GitHub Actions는 10분마다 각 등록 건을 조회하고, 권장 출발 시각이 20분 이내면 텔레그램으로 한 번 알립니다. 알림을 보낸 사실은 `state.json`에 남깁니다. 스케줄 실행은 몇 분 늦을 수 있으므로 알림 시각은 정확한 분 단위로 보장되지 않습니다.

저장소의 **Settings → Secrets and variables → Actions**에 다음 이름으로 등록해야 합니다.

- `KAKAO_REST_API_KEY`: 카카오디벨로퍼스 REST API 키
- `TELEGRAM_BOT_TOKEN`: BotFather가 발급한 봇 토큰
- `TELEGRAM_CHAT_ID`: 알림을 받을 대화 ID

설정 후 **Actions → Check departure alerts → Run workflow**로 수동 실행하고, 휴대폰 수신과 `state.json` 갱신을 확인합니다. 같은 조건으로 다시 실행했을 때 알림이 중복되지 않아야 합니다. 현재 실제 발송은 검증 전입니다.
